# Code Review Process

## Overview

Guidelines for effective code reviews.

## Checklist

### Functionality
- [ ] Code works as expected
- [ ] Edge cases handled
- [ ] Error handling present

### Code Quality
- [ ] Follows style guide
- [ ] DRY principles applied
- [ ] No code smells

### Testing
- [ ] Tests included
- [ ] Tests pass
- [ ] Coverage maintained

### Security
- [ ] No sensitive data exposed
- [ ] Input validation present
- [ ] Auth checks in place

## Review Guidelines

### For Reviewers
- Be constructive
- Explain the "why"
- Suggest alternatives
- Approve when ready

### For Authors
- Keep PRs small
- Write clear descriptions
- Respond to feedback
- Request re-review after changes

## Turnaround Time

- P1 bugs: Same day
- Features: 2 business days
- Docs: 3 business days
